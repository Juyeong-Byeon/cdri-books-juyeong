# ADR-0007: 범용 UI·도메인 바인딩 분리와 검색 훅 인터페이스

- **상태**: 승인 (Accepted)
- **결정·개정 일자**: 2026-10-24
- **결정자**: 변주영

## 배경

검색 결과와 찜 목록은 도서 카드 구조를 공유하지만 데이터를 얻는 방식은 다르다. 이번 과제에서는 범용 카드와 도메인 바인딩을 분리해 UI 자체와 상태 연결을 각각 검토·테스트할 수 있도록 한다.

## 결정

- React 컴포넌트 파일은 PascalCase(`BookCardItem.tsx`)로 작성한다. 커스텀 훅 파일은 내보내는 훅 이름과 같은 camelCase(`useBookSearch.ts`)로 작성하고, 유틸리티·매퍼·저장소 어댑터 등 함수 중심 파일도 camelCase(`formatBook.ts`, `bookMapper.ts`, `safeLocalStorage.ts`)로 작성한다. 설정·타입·저장소 파일은 기존 이름을 유지한다.
- 페이지 진입 컴포넌트는 `src/pages/<페이지 경로>/Page.tsx`에 둔다. 페이지에서만 사용하는 컴포넌트·훅·유틸리티·타입·에셋은 해당 페이지 아래에서 관리하며, 필요한 파일이 생길 때 `components/`, `hooks/`, `utils/`, `types/`, `assets/`를 추가한다.
- 여러 페이지가 공유하는 UI·레이아웃·도메인 코드만 공통 계층에 둔다. `Page.tsx`는 공통 레이아웃과 페이지 전용 컴포넌트를 조합한다.
- `src/components/ui/`는 `Book`, Zustand, API 모듈에 의존하지 않는다.
- `ExpandableCard`는 펼침 상태·토글·콘텐츠·액션 슬롯을 받는 범용 레이아웃과 접근성 동작을 담당한다. ISBN·찜 저장·가격 계산을 알지 않는다.
- `src/components/features/`의 `BookCardItem`은 `Book`을 받아 제목·표지·가격 표현과 찜 액션·구매 링크를 구성하고 범용 카드에 전달한다.
- 검색과 찜 목록은 같은 도메인 바인딩 컴포넌트를 재사용한다.
- `Button`, 입력 UI, Popover 등의 공통 요소는 실제 사용에 필요한 범위만 만든다. 사용하지 않는 변형과 범용 설정은 미리 추가하지 않는다.
- 검색 훅은 Query의 페이지를 목록으로 구성하고 UI에 필요한 상태와 동작을 반환한다. 오류 종류·다음 페이지 실패·재시도 기능을 숨기지 않는다.
- URL 조건 읽기(`useSearchConditions`), 제출(`useSearchSubmit`), 결과 조회(`useBookSearch`)를 분리한다. 입력·상세검색·결과 컴포넌트는 필요한 훅을 직접 소비하고, 페이지 전체 훅의 반환 타입을 컴포넌트 props 계약으로 사용하지 않는다.
- 교차 감지 훅 `useIntersectionObserver`는 옵션 객체의 `enabled`, `onIntersect`, `rootMargin`을 받고 관찰 대상 ref를 반환한다. Observer의 연결·해제를 맡고, `SearchResults`가 조회 훅의 추가 로딩 동작을 연결한다. 현재 사용 범위에 맞춰 검색 페이지의 `hooks/`에 둔다.

### 커스텀 훅의 반환 참조

훅 소비처가 내부 구현이나 현재 사용처의 참조 의존성을 조사하지 않고도 반환값을 Effect 의존성·props로 사용할 수 있도록, 다음 규칙을 모든 커스텀 훅에 적용한다.

- 훅에서 생성해 반환하는 객체·배열은 `useMemo`로 메모이제이션한다. 반환 객체 내부의 파생 객체·배열도 각각 `useMemo`로 구성해 바깥 객체의 참조를 불필요하게 바꾸지 않는다.
- 훅에서 생성해 반환하는 함수는 단독 반환인지 객체의 필드인지와 관계없이 `useCallback`으로 메모이제이션한다. 현재 소비처에 `memo`나 Effect가 있는지는 이 규칙의 적용 조건이 아니다.
- `useRef`의 ref, React state setter, 저장소에서 선택한 배열·액션처럼 이미 참조가 유지되는 값은 그대로 반환한다. 외부 라이브러리의 값은 해당 라이브러리의 참조 정책을 따르며, 같은 데이터에서 불필요한 복사본을 만들지 않는다.
- 단순 비교·속성 접근으로 얻은 boolean·number·string은 일반 계산으로 유지하고, 바깥 반환 객체의 의존성에 포함한다.
- 함수·계산이 읽는 반응형 값은 의존성 배열에 모두 포함한다. 입력 옵션이 객체라면 실제 사용하는 필드에 의존해, 같은 값으로 만든 새 옵션 객체만으로 반환 함수의 참조가 바뀌지 않도록 한다.
- Effect나 이벤트 실행 중에만 사용하는 지역 함수·객체는 외부 반환 참조가 아니므로 이 규칙의 대상이 아니다.
- 참조 유지의 범위는 같은 훅 인스턴스에서 의존값이 같은 일반 재렌더링이다. 의존값 변경·재마운트·React의 캐시 초기화 이후까지 같은 참조를 영구 보장하지 않는다. 캐시 초기화로 Effect가 다시 실행되더라도 올바르게 동작하도록 연결과 정리를 구성한다.

### 검색 훅의 책임

| 반환 정보                       | 의미                                                                 |
| ------------------------------- | -------------------------------------------------------------------- |
| books, totalCount               | 정규화된 현재 검색 결과와 전체 건수                                  |
| isIdle, isLoading, isEmpty      | 검색 전·최초 요청 중·성공 후 빈 결과 구분                            |
| error, isError                  | 최초 요청 실패 또는 기존 데이터가 있는 갱신 실패 구분에 필요한 정보  |
| isFetching                      | 최초·갱신·추가 요청을 포함한 요청 진행 여부                          |
| hasNextPage, isFetchingNextPage | 추가 요청 가능 여부와 진행 상태                                      |
| canLoadMore                     | 검색 조건·다음 페이지·진행 중 요청·오류를 고려한 추가 요청 허용 여부 |
| isFetchNextPageError            | 다음 페이지 요청 실패 여부                                           |
| loadMore, retry                 | 추가 페이지 요청과 최초·갱신 요청 재시도                             |
| retryNextPage                   | 기존 결과를 유지한 추가 페이지 재시도                                |

`isIdle`은 제출된 유효한 검색 조건이 없는 상태로 정의한다. Query v5에서 비활성 쿼리의 `isPending`만 보고 로딩 UI를 표시하지 않는다. `isEmpty`는 유효한 검색이 성공하고 목록이 비었을 때만 참이다.

오류 표시의 세부 규칙은 [ADR-0011](./0011-query-errors-and-render-boundary.md)을 따른다. 오류 처리를 위해 필요한 경우 훅 인터페이스를 확장하며, 반환 필드를 적게 만드는 것 자체를 목표로 삼지 않는다.

## 대안과 선택 이유

| 대안                                       | 평가                                                                                                  |
| ------------------------------------------ | ----------------------------------------------------------------------------------------------------- |
| BookCard가 도메인과 UI를 모두 담당         | 파일·props가 적어 작은 화면에서는 충분히 실용적이다.                                                  |
| 범용 ExpandableCard + 도메인 바인딩 (선택) | 공통 UI를 독립 검증하고 검색·찜 카드의 연결 책임을 분리할 수 있다. 대신 계층과 props 전달이 늘어난다. |

## 결과와 트레이드오프

레이아웃 변경 시 두 계층을 함께 수정할 수 있고, 과도한 슬롯·props는 가독성을 해칠 수 있다. 명확한 경계와 독립 검증을 우선하되 모든 컴포넌트를 같은 형태로 분리하지는 않는다.

반환 참조의 일관성을 훅 내부에서 책임지는 대신, 훅을 변경할 때 메모이제이션의 의존성 배열도 함께 관리해야 한다. 기존 `react-hooks/exhaustive-deps` 규칙으로 의존성 누락을 확인하며 별도 검증 파이프라인은 추가하지 않는다. 메모이제이션은 참조 재사용을 위한 최적화이며 렌더링 횟수 감소나 계산량 감소를 항상 보장하지 않는다.

범용 카드 테스트는 펼침·키보드·ARIA를 확인하고, 도메인 바인딩 테스트는 찜과 표시값 연결을 확인한다. 렌더링 횟수 감소나 파일 길이 감소를 자동으로 보장하지 않는다.
