# ADR-0009: 과제 구현 범위와 디자인·접근성 기준

- **상태**: 승인 (Accepted)
- **결정·개정 일자**: 2026-10-23
- **결정자**: 변주영

## 배경

3일 제출 기한 안에 요구된 사용자 흐름을 완성해야 한다. 기본 기능에 더해 URL 동기화, UI 계층 분리, 배포 환경 검색 검증까지 필수 범위로 선택했으므로 각 기능의 완료 조건을 구분한다.

## 결정

다음 항목을 필수 구현 범위로 둔다.

- Enter 검색, 상세검색, 전체·상세검색 상호 초기화
- 페이지당 10개 무한 스크롤
- 최근 검색어 최대 8개와 브라우저 재시작 후 복원
- 찜한 시점의 도서 스냅샷 보관과 같은 앱의 검색·찜 화면 간 상태 공유
- 카드 상세 펼침, 새 탭 구매 링크, 초기·빈 결과·오류·로딩 화면
- 기준 디자인 재현과 키보드 조작
- 검색 조건·탭 URL 동기화와 뒤로가기·앞으로가기
- Vitest·RTL·MSW 핵심 테스트와 실제 배포 검색 검증

### 디자인과 접근성

- 작은 표지 48×68px, 펼친 표지 210×280px에 맞춰 로드 전부터 공간을 확보한다. 모든 표지에 같은 종횡비를 강제하지 않는다.
- 빈 URL·이미지 실패는 대체 표시로 처리한다. 폴백 실패가 반복 로드를 만들지 않도록 한다.
- 찜 버튼에는 도서명을 포함한 접근 가능한 이름과 `aria-pressed`를 제공한다.
- 상세 토글은 `aria-expanded`를 제공하고 펼친 상세 영역의 ID를 `aria-controls`로 연결한다.
- 상세검색은 [ADR-0002](./0002-styling-tailwind-css.md)의 Popover와 선택 입력으로 구현한다.
- 구매 링크는 API가 제공한 도서 URL을 새 탭으로 열며 `rel="noopener noreferrer"`를 적용한다.
- 라이브러리 채택만으로 접근성이나 CLS 0을 보장하지 않는다. 화면 비교와 키보드 검증을 수행한다.

## 대안과 선택 이유

기본 검색·찜 기능만 우선 완성하고 URL 동기화를 후순위로 둘 수 있다. 이번에는 URL 공유·새로고침·브라우저 이동까지 일관된 동작을 보여주기 위해 URL 동기화도 필수로 선택했다.

## 결과와 트레이드오프

기본 범위보다 구현·검증 비용이 커진다. 추가 자동 검색, 가상화, Storybook, Playwright 도입은 이번 필수 범위에 포함하지 않는다. 기능별로 구현과 검증 결과를 기록하며, 설계 승인만으로 구현 완료를 표시하지 않는다.
