# ADR-0014: PageSpeed 근거로 폰트·아이콘·크롤링·텍스트 대비 개선

- **상태**: 승인 (Accepted)
- **결정 일자**: 2026-10-24
- **결정자**: 변주영

## 배경

공개 배포의 초기 화면과 검색 결과에 대한 PageSpeed Insights 보고서에서 Google Fonts의 렌더링 차단·중복 CSS, `robots.txt`의 HTML 응답, 검색 결과의 텍스트 대비 문제가 확인됐다. 자산 확인 과정에서는 빈 상태 아이콘이 SVG 안에 큰 PNG를 포함하고 있었다.

보고서의 권고만으로 구조를 늘리지 않고, 실제 원인이 확인된 요청·자산·스타일을 수정한다. 보고서 원본·측정 환경·점수·캡처와 크기·대비율 비교는 [성능 측정 기록](../performance/index.md)에 둔다.

## 결정

### 폰트와 아이콘

- [폰트 요청](../../index.html)은 Noto Sans KR의 개별 굵기 나열에서 가변 굵기 범위 요청으로 바꾼다. 같은 브라우저 조건에서 참조하는 폰트 파일 집합이 동일함을 확인했으므로, 글꼴을 바꾸지 않고 중복 CSS 선언을 줄일 수 있다. 기존 `display=swap`과 사전 연결은 유지한다.
- [빈 상태 아이콘](../../src/components/features/book/assets/empty-books.svg)은 내장 PNG를 제거하고 원·표지·책장을 실제 SVG 도형으로 표현한다. 단순한 도형에 큰 래스터 원본을 전송할 필요가 없으며, 기존 표시 공간은 유지한다.
- 파비콘도 같은 SVG 원본을 참조한다. 별도 아이콘 사본을 수동으로 맞추는 작업을 만들지 않는다.

### 크롤링과 가독성

- [robots.txt](../../public/robots.txt)를 정적 텍스트로 제공한다. 파일 누락으로 SPA fallback이 앱 HTML을 반환한 원인을 해결하며, 앱 경로의 fallback은 유지한다.
- 일반 크기 텍스트와 흰색 버튼 글자는 충분한 대비를 갖도록 색상 토큰을 보완한다. 원본 주 색상은 탐색 메뉴·포커스 표시에 유지하고, 텍스트·버튼 역할에는 대비를 확보한 토큰을 적용한다. 토큰의 정의·사용 방식은 [ADR-0002](./0002-styling-tailwind-css.md)를 따른다.

### 후속 최적화와 측정

- 외부 표지는 API에서 제공하는 썸네일 URL을 사용한다. 작은 목록 표지와 펼친 표지, 고해상도 화면의 품질을 함께 고려해야 하므로 문서화되지 않은 이미지 변환 URL을 추측해 적용하지 않는다.
- 미사용 JavaScript 예상치만으로 청크 분리나 새 의존성을 도입하지 않는다. 해당 코드가 어떤 화면에서 필요한지와 실제 로딩·상호작용 비용을 확인한 뒤 결정한다.
- 공개 사이트의 개선 효과를 주장할 때는 재배포 후 같은 URL·기기·네트워크 조건으로 다시 측정한다. 서로 다른 화면의 점수나 로컬 자산 크기 비교를 개선 전·후의 PageSpeed 결과로 표시하지 않는다.
- 단일 실행의 실험실 점수와 실제 사용자 데이터는 구분한다. 자동 접근성 감사는 [ADR-0012의 실제 환경 검증](./0012-testing-and-deployment-validation.md)을 대신하지 않는다.

## 대안과 선택 이유

| 대안                                     | 평가                                                                                                                                       |
| ---------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------ |
| 폰트를 자체 호스팅                       | 외부 CSS 요청을 없앨 수 있지만 폰트 갱신 때마다 파일·서브셋·캐시 정책을 관리해야 한다. 현재 확인한 중복은 요청 형식 변경으로 줄일 수 있다. |
| 이미지 프록시 추가                       | 표지를 크기별로 가공할 수 있지만 이미지 처리·캐시·오류 경로를 변경마다 관리해야 한다. 현재 표지 사용량과 품질 요구만으로 추가하지 않는다.  |
| 원본 주 색상을 모든 역할에서 교체        | 적용은 단순하지만 탐색·포커스까지 디자인을 변경한다. 대비 문제가 있는 텍스트·버튼 역할에 토큰을 구분해 적용한다.                           |
| 확인한 원인의 자산·요청·토큰 수정 (선택) | 기존 기능과 배포 구조 안에서 전송량·크롤링 오류·가독성을 개선하며 새 런타임 서비스를 추가하지 않는다.                                      |

## 결과와 트레이드오프

외부 폰트 요청은 남으므로 네트워크와 캐시 상태의 영향을 계속 받는다. 아이콘 디자인이 바뀌면 SVG 도형을 수정해야 하며, 대비를 보완한 색상은 원본 디자인과 일부 달라진다.

새 의존성·서비스·배포 게이트는 추가하지 않는다. 기존 빌드가 자산과 문서를 생성하며, 아이콘·색상·폰트 변경 시 제품 코드의 원본을 수정한다. 수치와 캡처는 측정 기록에서만 관리한다.

로컬 빌드와 미리보기 확인은 공개 배포의 새 점수를 증명하지 않는다. 변경 반영 및 재측정 여부는 [성능 측정 기록](../performance/index.md)에서 구분해 기록한다.
