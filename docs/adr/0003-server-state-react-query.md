# ADR-0003: 제출된 검색 조건과 TanStack Query 기반 무한 스크롤

- **상태**: 승인 (Accepted)
- **결정·개정 일자**: 2026-10-23
- **결정자**: 변주영

## 배경

기획은 Enter로 검색을 확정하고, 결과를 페이지당 10개씩 무한 스크롤로 보여주도록 한다. 입력 중인 값이 확정 검색 조건을 바꾸거나, 이전 검색의 추가 페이지가 새 결과에 섞여서는 안 된다.

## 결정

- 서버 상태는 TanStack Query v5의 `useInfiniteQuery`에서 관리한다. 결과를 Zustand나 별도 로컬 상태에 복사하지 않는다.
- 검색은 Enter 또는 명시적인 검색 제출 동작으로 시작한다. 타이핑에 따른 자동 검색과 디바운싱은 도입하지 않는다.
- 검색 기록 선택도 제출 동작으로 취급한다. 전체·상세검색은 동시에 적용하지 않는다.
- 확정 검색 조건은 [ADR-0010](./0010-url-search-state-and-history.md)의 URL에서 읽고, 입력 중인 값은 로컬 상태로 둔다.
- 쿼리 키는 `getBookSearchQueryKey`에서 정규화된 검색어·대상·정렬·페이지 크기로 구성한다. 예: `['books', { searchKeyword, target, sort, size: 10 }]`.
- 첫 페이지는 1, 페이지 크기는 10으로 요청한다. 페이지 번호는 쿼리 키와 URL에 넣지 않고 `pageParam`으로 관리한다.
- 검색어가 비어 있으면 쿼리를 비활성화한다. 검색 전 상태와 검색 성공 후 빈 결과를 구분한다.
- `getNextPageParam`은 매핑된 페이지의 `meta.isEnd`, 빈 도서 목록, API의 허용 페이지 범위를 기준으로 종료한다.
- 추가 요청 가능 여부는 `useBookSearch`의 `canLoadMore`와 `loadMore`에서 결정한다. 실패 후에는 관찰만으로 반복 요청하지 않고 재시도 UI를 제공한다.
- 교차 감지는 `useIntersectionObserver`가 맡고, 관찰 활성화·콜백·여유 범위는 `SearchResults`에서 옵션으로 전달한다. 교차 감지 훅은 Query와 도서 데이터에 의존하지 않는다.
- 쿼리의 `AbortSignal`을 HTTP 요청에 전달한다. 조건 변경 시 새 쿼리 키를 사용하고 기존 페이지를 새 결과에 합치지 않는다.
- 동일 식별자의 중복 문서는 목록을 구성하는 단계에서 정리한다.

## 대안과 선택 이유

| 대안                                   | 평가                                                                     |
| -------------------------------------- | ------------------------------------------------------------------------ |
| useEffect와 수동 페이지 상태           | 취소·캐시·오류·누적 결과를 직접 관리해야 하며 필수 기술 활용도 제한된다. |
| 입력 디바운싱 검색                     | 자동 검색에는 적합하지만 이번 Enter 제출 흐름과 다르다.                  |
| TanStack Query와 제출 기반 검색 (선택) | 요청 수명과 페이지 누적을 라이브러리에 맡기면서 기획을 따른다.           |

## 결과와 트레이드오프

캐시가 남아 있으면 같은 조건의 결과를 재사용할 수 있다. 캐시 유지 시간과 데이터의 신선도에 따라 재요청이 가능하므로 탭 복귀 시 요청이 항상 0회라고 보장하지 않는다. `staleTime`과 `gcTime`의 역할을 구분한다.

무한 스크롤 위치와 로드한 페이지 수는 새로고침 시 복원을 보장하지 않는다. URL 조건으로 다시 검색할 수 있어야 한다.

## 구현 시 확인

입력만으로 요청하지 않음, 전체·상세 조건 전환, 요청당 10개, 중복 추가 요청 방지, 마지막 페이지 종료, 조건 변경 시 페이지 분리, 초기·추가 페이지 오류 복구를 [ADR-0012](./0012-testing-and-deployment-validation.md)에 따라 검증한다.
