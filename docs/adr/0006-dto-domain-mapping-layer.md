# ADR-0006: DTO·도메인·매퍼를 분리하고 표시 포맷은 별도로 처리

- **상태**: 승인 (Accepted)
- **결정·개정 일자**: 2026-10-22
- **결정자**: 변주영

## 배경

API 응답에는 snake_case 필드, 복합 ISBN, 미제공 가격, 빈 썸네일 등이 있다. UI에서 이 예외 처리를 반복하지 않으면서, 가격 계산과 찜 데이터 복원에 필요한 원래 의미를 유지해야 한다.

## 결정

- DTO는 `src/types/dto/`, 도메인 모델은 `src/types/domain/`, 변환 순수 함수는 `src/services/mappers/`에 분리한다.
- API 계층에서 DTO를 `Book`과 페이지 메타데이터로 변환한다. UI와 영속 저장소는 DTO를 직접 소비하지 않는다.
- 매퍼는 필드명과 미제공값을 정규화한다. 숫자 가격, 저자 배열, 발행일 데이터의 의미를 유지한다.
- 도메인 필드의 예시는 `price: number | null`, `salePrice: number | null`, `authors: string[]`, `publishedAt: string | null`이다. 날짜는 직렬화 가능한 ISO 문자열로 유지한다.
- `sale_price: -1` 등 미제공 가격은 `null`로 정규화하며, 유효한 0원과 구별한다.
- 원화 표시, 저자명 연결, 날짜 표시, 할인 여부와 같은 표현·파생 로직은 포맷 함수 또는 선택자로 처리한다. 표시 문자열을 `Book`의 기본 데이터로 저장하지 않는다.
- ISBN 문자열을 분리해 유효한 ISBN-13을 우선하고, 없으면 ISBN-10을 사용한다. ISBN이 없으면 API가 제공한 URL을 대체 식별자로 사용한다.
- ID에 `isbn:`·`url:` 같은 접두사를 사용해 종류를 구분한다. 렌더링 인덱스나 난수로 ID를 만들지 않는다. ISBN과 URL이 모두 없는 응답은 식별 불가능 데이터로 처리한다.
- 찜은 이 `Book`의 스냅샷을 저장한다. 저자 배열 등 참조 데이터가 나중에 변경되어 저장 내용이 달라지지 않게 한다.

## 대안과 선택 이유

| 대안                                         | 평가                                                               |
| -------------------------------------------- | ------------------------------------------------------------------ |
| UI에서 DTO 직접 사용                         | 코드가 적지만 데이터 예외 처리와 API 필드 의존이 화면으로 퍼진다.  |
| 매퍼에서 모든 표시 문자열 생성               | 초기 렌더링은 단순하지만 정렬·가격 계산·표시 형식 변경에 불리하다. |
| 의미를 유지한 도메인과 별도 포맷 함수 (선택) | 데이터 정규화와 화면 표현의 변경 이유를 분리한다.                  |

## 결과와 트레이드오프

DTO·도메인·매퍼·포맷 함수 파일과 변환 테스트가 추가된다. 단일 API에 대한 추상화 비용을 감수하고, 검색·찜 화면이 같은 도메인 계약을 공유하도록 한다.

외부 스펙 변경이 항상 매퍼 하나로 끝나는 것은 아니다. 도메인 의미가 바뀌면 UI와 저장소도 함께 변경될 수 있다. 가격·날짜를 문자열로 미리 가공하던 기존 설계를 이 결정으로 대체한다.

## 구현 시 확인

복합·단일·빈 ISBN, URL 대체 ID, 0원·미제공 가격, 빈 저자·날짜·썸네일, JSON 저장·복원 후 데이터 의미 유지, 표시 함수의 가격·저자·날짜 포맷을 검증한다.
