# ADR-0004: Zustand persist로 찜 스냅샷과 최근 검색어 저장

- **상태**: 승인 (Accepted)
- **결정·개정 일자**: 2026-10-23
- **결정자**: 변주영

## 배경

검색 결과와 찜 목록은 찜 상태를 공유해야 한다. 찜한 시점의 도서 정보와 최근 검색어는 브라우저를 다시 시작해도 남아 있어야 한다. 검색 결과 캐시와 사용자 보관 데이터는 수명이 다르다.

## 결정

- Zustand 저장소는 상태 도메인별로 분리해 찜 상태는 `src/stores/favorites/`, 검색 기록은 `src/stores/searchHistory/`에 둔다.
- 저장소들이 공유하는 영속화 보조 코드는 `src/stores/util/`에 둔다. 현재 `safeLocalStorage.ts`가 이 위치에 있다.
- 파일명 규칙은 [ADR-0007](./0007-component-and-hook-layering.md)을 따른다.
- 검색 기록의 상태와 액션은 일반적인 `term`보다 의미가 분명한 `searchKeyword` 이름을 사용한다.
- Zustand와 `persist`를 유지하고 `localStorage`에 저장한다.
- `useFavoritesStore`와 `useSearchHistoryStore`를 분리한다.
- 찜에는 [ADR-0006](./0006-dto-domain-mapping-layer.md)의 `Book`을 찜한 시점의 스냅샷으로 저장한다. ID만 저장하거나 재조회 결과로 자동 갱신하지 않는다.
- 식별자로 찜을 추가·해제하며, 검색 화면과 찜 화면은 동일 저장소를 사용한다. 빈 목록도 명시적으로 표시한다.
- 최근 검색어는 공백을 정리한 제출 검색어를 최신순으로 최대 8개 보관한다. 중복 검색어는 맨 앞으로 이동하고 9번째부터 오래된 항목을 제거한다.
- 검색 기록의 개별·전체 삭제를 지원한다. 입력 중·조회 실패 재시도·URL 뒤로가기만으로 기록을 추가하지 않는다.
- URL 검색 조건, 활성 탭, API 결과, 팝업 열림 상태는 이 저장소에 중복 저장하지 않는다.
- 저장 가능한 데이터만 영속화한다. 저장소 읽기·쓰기 실패나 손상된 데이터 때문에 전체 화면이 중단되지 않도록 처리한다.
- 저장된 검색 기록은 `searchKeywords`로 복원하고, 이전 `terms` 형식도 마이그레이션한다. 복원 과정에서도 공백·중복·개수 제한을 정리한다.

## 대안과 선택 이유

| 대안                             | 평가                                                                 |
| -------------------------------- | -------------------------------------------------------------------- |
| Context + useReducer + 저장 로직 | 충분히 구현 가능하지만 저장·복원과 구독 범위를 별도로 관리해야 한다. |
| Redux Toolkit                    | 규모가 커질 때 유용하지만 이번 두 저장소에는 추가 구성이 필요하다.   |
| Zustand + persist (선택)         | 기존 의존성을 활용하고 선택적 구독과 영속화 로직을 함께 구성한다.    |

## 결과와 트레이드오프

찜 데이터는 현재 API 응답과 다를 수 있으며, 이는 기획에 따른 동작이다. 저장소 스키마 변경 시 기존 데이터의 호환성 또는 마이그레이션을 고려해야 한다. 브라우저 데이터 삭제·용량 제한 등으로 보관을 보장할 수 없는 경우도 있다.

각 카드에서는 필요한 값과 액션만 구독한다. 셀렉터가 저장소 변경에 따른 불필요한 갱신을 줄일 수 있지만 부모 렌더링 등까지 차단하거나 리렌더링 0회를 보장하지는 않는다.

## 구현 시 확인

찜 추가·해제·중복 방지·복원·스냅샷 유지, 최근 검색어 중복 이동·최대 8개·삭제·복원, 손상된 저장 데이터 처리와 테스트 간 저장소 격리를 검증한다.
