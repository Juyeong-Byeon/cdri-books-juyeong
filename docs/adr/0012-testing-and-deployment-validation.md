# ADR-0012: Vitest·RTL·MSW 핵심 테스트와 실제 배포 검증

- **상태**: 승인 (Accepted)
- **결정·개정 일자**: 2026-10-23
- **결정자**: 변주영

## 배경

제한된 제출 시간 안에 데이터 예외와 주요 사용자 흐름을 반복 검증해야 한다. 테스트가 실제 카카오 응답·인증·네트워크에 의존하면 실패 원인을 분리하기 어렵다. 반면 모의 응답만으로는 프록시와 배포 환경 연동을 증명할 수 없다.

## 결정

- Vitest를 실행기로, React Testing Library와 user-event를 화면 조작에 사용한다.
- MSW로 애플리케이션의 `/api/books` 요청을 네트워크 경계에서 모의 처리한다. 실제 API 키 없이 자동 테스트를 실행한다.
- 기본 자동화 범위는 단위·컴포넌트·통합 테스트로 정한다. Playwright 추가는 이번 필수 범위에서 제외한다.
- 테스트마다 새 QueryClient를 사용하고 종료 시 정리한다. Zustand·localStorage·MSW 핸들러와 현재 URL을 초기화해 실행 순서에 의존하지 않게 한다. 브라우저 방문 기록 전체 삭제 대신 테스트별 진입점을 설정하고 상대적인 push·replace 및 뒤로가기·앞으로가기 동작을 검증한다.
- 미처리 네트워크 요청은 테스트 실패로 취급한다. 재시도 정책 테스트는 실제 결정한 정책을 검증한다.

### 필수 검증 범위

| 대상                  | 검증할 동작                                                                   |
| --------------------- | ----------------------------------------------------------------------------- |
| 도메인 매퍼·포맷 함수 | 복합·빈 ISBN, URL 대체 ID, 0원·미제공 가격, 빈 필드, 표시 형식                |
| 찜 저장소             | 추가·해제·중복 방지·저장 복원·찜 시점 스냅샷 유지                             |
| 검색 기록             | 제출 기록·중복 이동·최대 8개·삭제·저장 복원                                   |
| 검색 제출             | 입력만으로 요청하지 않음, Enter 제출, 공백 처리                               |
| 상세검색              | 대상 전달, 전체·상세 상호 초기화, 팝업 제출·취소                              |
| 무한 스크롤           | 크기 10, 다음 페이지, 중복 요청 방지, 종료, 조건 변경 시 분리                 |
| 오류 복구             | 초기 오류, 인증 재시도 방지, 추가 페이지 실패와 기존 결과 유지                |
| URL 어댑터            | 파싱·직렬화·정규화, push와 replace, 화면·입력의 위치 변경 구독, popstate 복원 |
| 공통 UI·도메인 바인딩 | 카드 펼침·ARIA, 팝업 키보드와 포커스, 찜 액션 연결                            |

### 실제 환경에서 별도로 확인

- 로컬 프록시에서 한글 검색어·검색 대상·페이지가 업스트림까지 유지되는지 확인한다.
- Cloudflare 배포 후 직접 URL 접속, 새로고침, 검색과 다음 페이지 로딩을 확인한다.
- 브라우저 뒤로가기·앞으로가기·탭 전환의 조건 복원과 실제 브라우저 재시작 후 찜·기록 복원을 확인한다.
- 브라우저 요청과 번들에 인증 키가 전달되지 않는지 확인한다.
- 기준 화면의 디자인, 키보드 조작, 팝업 포커스를 실제 브라우저에서 확인한다.

## 대안과 선택 이유

| 대안                                     | 평가                                                                              |
| ---------------------------------------- | --------------------------------------------------------------------------------- |
| 수동 검증만 수행                         | 초기 비용은 적지만 데이터 예외와 회귀를 반복 확인하기 어렵다.                     |
| Vitest·RTL만 사용하고 서비스 함수를 모킹 | 가볍지만 요청 URL·파라미터와 오류 응답 경계를 놓칠 수 있다.                       |
| Vitest·RTL·MSW와 별도 배포 검증 (선택)   | 네트워크 계약을 포함한 반복 검증과 실제 연결 검증을 분리한다.                     |
| Playwright까지 필수로 도입               | 브라우저 동작 자동화는 강화되지만 설치·브라우저 실행·테스트 관리 비용이 늘어난다. |

## 결과와 트레이드오프

MSW와 테스트·핸들러 구성이 추가로 필요하다. JSDOM은 실제 레이아웃·스크롤·브라우저 방문 기록을 완전히 재현하지 않으므로 실제 환경 검증을 남긴다. 테스트용 IntersectionObserver 모의 구현만으로 브라우저 무한 스크롤 동작을 입증하지 않는다.

MSW와 위 필수 범위의 단위·컴포넌트·통합 테스트를 추가했다. 개발 프록시는 실제 Vite 서버를 실행하고, 배포 프록시는 Function 핸들러에 요청을 전달해 모의 업스트림과의 계약을 검증한다. 이는 Cloudflare 런타임·배포 검증을 대신하지 않는다.

테스트 수와 실행 결과, 남은 실제 환경 검증은 [README의 자동 검증 현황](../../README.md#자동-검증-현황)에 기록한다. 0개 테스트 실행은 통과 증거가 아니다.
