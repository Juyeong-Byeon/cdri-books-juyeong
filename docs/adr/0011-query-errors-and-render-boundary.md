# ADR-0011: React Query 오류 UI와 렌더링 ErrorBoundary 분리

- **상태**: 승인 (Accepted)
- **결정 일자**: 2026-10-22
- **결정자**: 변주영

## 배경

API 실패와 React 렌더링 예외는 발생·복구 방식이 다르다. 특히 다음 페이지 요청 실패 때문에 이미 읽던 결과를 제거해서는 안 된다. 일반 ErrorBoundary는 비동기 API 실패를 자동으로 처리하지 않는다.

## 결정

- API 실패는 React Query의 오류 상태와 UI로 처리한다. API 실패를 ErrorBoundary로 보내기 위한 `throwOnError`는 사용하지 않는다.
- 도서 영역의 ErrorBoundary는 렌더링 예외를 담당하고, 헤더와 탭은 경계 밖에 둔다.
- 최초 요청 실패, 기존 데이터가 있는 갱신 실패, 다음 페이지 실패를 구분한다.
- 다음 페이지 실패 후 기존 목록을 유지하고 목록 끝에 재시도 동작을 제공한다. 관찰 대상이 계속 보인다는 이유만으로 요청을 반복하지 않는다.
- 사용자가 검색 조건을 바꿀 수 있는 상태를 유지하고, 네트워크 오류를 빈 검색 결과로 표시하지 않는다.

### 상태와 복구

| 상황                    | 표시·동작                                           |
| ----------------------- | --------------------------------------------------- |
| 유효한 검색 조건 없음   | 초기 화면, 네트워크 요청 없음                       |
| 최초 요청 중            | 로딩 UI                                             |
| 성공 후 0건             | 빈 결과 UI                                          |
| 최초 요청 실패          | 원인에 맞는 오류 설명, 복구 가능한 경우 검색 재시도 |
| 기존 데이터의 갱신 실패 | 기존 목록 유지, 갱신 실패 안내와 재시도             |
| 다음 페이지 실패        | 기존 목록 유지, 추가 페이지 재시도                  |
| 렌더링 예외             | 영역 단위 대체 UI와 경계 초기화 또는 화면 재진입    |

### 재시도 정책

- 401·403은 자동 재시도하지 않는다. 키나 권한을 확인해야 하는 오류임을 알린다.
- 400 등 잘못된 요청과 429 제한 응답도 즉시 자동 반복하지 않는다.
- 네트워크 단절과 5xx는 자동 재시도를 최대 1회로 제한한다.
- 최초·갱신 요청의 재시도와 다음 페이지 재시도를 분리한다. 렌더링 경계의 초기화만으로 API가 재요청된다고 가정하지 않는다.
- 오류 메시지와 로그에 API 키나 원본 인증 헤더를 포함하지 않는다.

## 대안과 선택 이유

| 대안                                    | 평가                                                                     |
| --------------------------------------- | ------------------------------------------------------------------------ |
| 최초 API 실패도 ErrorBoundary로 전달    | 대체 화면은 모을 수 있지만 경계 초기화와 쿼리 복구를 함께 관리해야 한다. |
| 모든 API 실패를 공통 오류 화면으로 전환 | 단순하지만 기존 목록과 추가 페이지 재시도 맥락을 잃기 쉽다.              |
| Query 오류 UI와 렌더링 경계 분리 (선택) | 요청 종류에 맞게 기존 데이터를 유지하고 복구 동작을 제공한다.            |

## 결과와 트레이드오프

화면과 검색 훅에서 여러 상태를 구분해야 한다. 오류 여부만 반환하는 얇은 래퍼로 축약하지 않고 [ADR-0007](./0007-component-and-hook-layering.md)의 오류·재시도 계약을 유지한다.

## 구현 시 확인

인증 오류 자동 재시도 없음, 네트워크·서버 오류의 제한된 재시도, 최초 실패 후 복구, 추가 페이지 실패 시 기존 데이터 유지, 렌더링 오류 시 헤더·탭 유지와 경계 복구를 검증한다.
