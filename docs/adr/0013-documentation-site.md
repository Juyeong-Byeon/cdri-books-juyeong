# ADR-0013: Markdown 원본을 VitePress로 생성해 Pages에 함께 배포

- **상태**: 승인 (Accepted)
- **결정 일자**: 2026-10-23
- **결정자**: 변주영

## 배경

배포된 앱과 함께 README·ADR을 읽기 좋은 형태로 공유한다. 별도 문서 사본이나 손으로 유지하는 내비게이션 목록을 만들면 문서를 수정할 때마다 두 곳을 맞춰야 한다.

## 결정

- VitePress 기본 테마로 정적 문서 사이트를 생성한다. 앱은 기존 React 구성을 유지하고, 문서 도구는 개발 의존성으로 사용한다.
- 문서 본문은 루트 `README.md`와 `docs/adr/*.md`에서 관리한다. `docs/index.md`는 README를 포함하고, 배포용 Markdown 사본을 만들지 않는다.
- 사이트와 링크 변환은 [문서 설정](../.vitepress/config.ts)에서 관리한다. ADR 사이드바는 디렉터리의 파일명과 첫 제목에서 자동으로 생성한다.
- GitHub에서 사용하는 상대 Markdown 링크는 문서 경로로 변환하고, 코드 파일 링크는 GitHub 원문으로 연결한다. 원본 문서는 GitHub에서도 그대로 읽을 수 있어야 한다.
- 검색·문서 내 목차·화면 모드·모바일 메뉴는 기본 테마의 기능을 사용한다.
- 기존 빌드 명령에 문서 생성을 포함해 앱과 문서를 하나의 Pages 배포로 제공한다. 명령과 공개 경로는 [README의 문서 안내](../../README.md#46-문서-사이트)를 따른다.

## 대안과 선택 이유

| 대안                           | 평가                                                                       |
| ------------------------------ | -------------------------------------------------------------------------- |
| GitHub Markdown 링크만 공유    | 추가 빌드가 없지만 앱과 같은 사이트의 문서 탐색·검색을 제공하지 못한다.    |
| React 안에 문서 뷰어 직접 구현 | 기존 UI를 활용할 수 있지만 Markdown 렌더링·탐색·검색을 직접 관리해야 한다. |
| VitePress 정적 문서 (선택)     | 기본 문서 UI를 사용하고, 같은 Markdown을 앱과 함께 배포할 수 있다.         |

## 결과와 트레이드오프

의존성과 문서 빌드 단계가 추가된다. 이후 앱·문서 변경을 배포할 때마다 문서 생성 시간이 더해진다. 본문과 사이드바를 별도로 동기화하는 수작업은 추가하지 않는다.

정적 HTML과 문서 자산은 앱의 출력 폴더 안에 생성하며, 도서 검색 API 프록시는 기존 Pages Function을 사용한다. 빌드 산출물과 문서 캐시는 Git에서 제외한다.
