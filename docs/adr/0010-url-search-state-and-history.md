# ADR-0010: URL을 확정 검색 조건의 기준으로 사용

- **상태**: 승인 (Accepted)
- **결정 일자**: 2026-10-22
- **결정자**: 변주영

## 배경

검색 결과 링크 공유, 새로고침 복원, 뒤로가기·앞으로가기를 지원한다. URL과 별도 전역 검색 상태를 동시에 기준으로 삼으면 서로 덮어쓰거나 방문 기록이 중복될 수 있다. 입력 도중에는 요청과 URL을 바꾸지 않아야 한다.

## 결정

URL을 확정 검색 조건과 활성 탭의 단일 기준으로 사용한다. 입력·팝업의 임시 상태는 별도로 두며 제출할 때만 URL을 변경한다.

### URL 계약

| 파라미터 | 의미          | 기본값·정규화                                   |
| -------- | ------------- | ----------------------------------------------- |
| q        | 확정 검색어   | 비어 있으면 검색하지 않음, 양끝 공백 제거       |
| target   | 상세검색 대상 | 없으면 전체검색, title·person·publisher 중 하나 |
| sort     | 정렬          | accuracy 기본, latest 허용                      |
| tab      | 활성 탭       | search 기본, favorites 허용                     |

- 전체검색은 `target`을 제거하고, 상세검색은 선택한 `target`과 검색어를 함께 기록한다.
- 알 수 없는 허용값은 기본값으로 해석하고, 필요 시 `replaceState`로 정규화한다. 검색어 인코딩은 `URLSearchParams`로 처리한다.
- 무한 스크롤의 현재 페이지·로드한 페이지 수·스크롤 위치는 URL에 넣지 않는다.
- 예시: `?q=리액트&target=title&sort=accuracy&tab=search`.

### 제출·탭·방문 기록

- 검색 제출과 탭 전환에는 `pushState`를 사용한다. URL 정규화는 `replaceState`를 사용해 추가 방문 기록을 만들지 않는다.
- 탭을 바꿔도 확정된 검색어·대상·정렬을 유지한다. 찜 탭에서는 검색 결과를 표시하지 않으며, 검색 탭으로 돌아오면 같은 조건을 사용한다.
- 상세검색 제출 시 전체검색 입력을 비우고 상세 조건을 적용한다. 전체검색 제출 시 상세검색 입력·조건을 초기화한다.
- 팝업 열기·입력·취소는 확정 조건을 바꾸지 않는다.
- 뒤로가기·앞으로가기는 URL에서 탭과 확정 조건을 다시 읽는다. 검색 입력도 해당 조건에 맞춰 복원하고 팝업은 닫는다.
- 방문 기록 복원 자체는 새로운 방문 기록이나 최근 검색 기록을 추가하지 않는다.
- 새로고침은 조건을 복원한다. 결과 데이터는 필요하면 다시 요청하며, 스크롤 위치나 이전 페이지 수까지 복원을 보장하지 않는다.

### 구현 규칙

- 두 탭에는 별도 경로가 필요하지 않으므로 우선 표준 `URLSearchParams`와 History API를 공통 어댑터로 감싼다.
- 파싱·정규화·직렬화는 순수 함수로 분리한다. URL을 쓰는 곳에서 직접 흩어져 `pushState`를 호출하지 않는다.
- `popstate` 구독과 해제를 관리한다. `pushState`·`replaceState`는 `popstate`를 자동 발생시키지 않으므로 어댑터가 구독자에게 변경을 알린다.
- React Query 키는 어댑터가 읽은 확정 조건에서 만든다. Zustand에 같은 검색 조건을 저장하거나 효과 훅끼리 URL·상태를 왕복 복사하지 않는다.

## 대안과 선택 이유

| 대안                                          | 평가                                               |
| --------------------------------------------- | -------------------------------------------------- |
| 검색 상태는 useState·Zustand, URL은 부가 복사 | 양방향 동기화의 충돌·초기화 순서를 관리해야 한다.  |
| URL 기준, 검색만 push·탭은 replace            | 기록은 적지만 탭 이동을 뒤로가기로 되돌릴 수 없다. |
| URL 기준, 검색과 탭 모두 push (선택)          | 확정한 사용자 이동을 방문 기록으로 복원할 수 있다. |

## 결과와 트레이드오프

탭 전환도 방문 기록을 늘린다. 네이티브 History API에는 React 렌더링 구독을 직접 연결해야 한다. 라우팅 범위가 커지면 라우터 도입을 재검토한다.

## 구현 시 확인

직접 URL 접속, 한글 인코딩, 잘못된 파라미터, 전체·상세 전환, 입력 중 URL 불변, 탭 이동 후 조건 유지, 뒤로가기·앞으로가기, 새로고침과 어댑터 알림을 검증한다.
