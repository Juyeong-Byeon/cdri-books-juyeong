# ADR-0010: URL을 검색 조건의 기준으로 사용하고 React Router로 화면 이동

- **상태**: 승인 (Accepted)
- **결정 일자**: 2026-10-22
- **결정자**: 변주영

## 배경

검색 결과 링크 공유, 새로고침 복원, 뒤로가기·앞으로가기를 지원한다. URL과 별도 전역 검색 상태를 동시에 기준으로 삼으면 서로 덮어쓰거나 방문 기록이 중복될 수 있다. 입력 도중에는 요청과 URL을 바꾸지 않아야 한다.

## 결정

확정 검색 조건은 URL의 검색 파라미터를 기준으로 삼고, 현재 화면은 React Router 경로로 결정한다. 검색 입력과 팝업의 임시 상태는 로컬 상태로 관리하며 제출할 때만 URL을 변경한다.

### URL 계약

| URL 요소     | 의미           | 기본값·정규화                                   |
| ------------ | -------------- | ----------------------------------------------- |
| `/`          | 도서 검색 화면 | 기본 경로                                       |
| `/favorites` | 찜한 책 화면   | 찜 목록을 표시하고 검색 결과는 표시하지 않음    |
| `q`          | 확정 검색어    | 비어 있으면 검색하지 않음, 양끝 공백 제거       |
| `target`     | 상세검색 대상  | 없으면 전체검색, title·person·publisher 중 하나 |
| `sort`       | 정렬           | accuracy 기본, latest 허용                      |

- 현재 화면은 경로로 표현하고 `tab` 검색 파라미터는 사용하지 않는다.
- 전체검색은 `target`을 제거하고, 상세검색은 선택한 `target`과 검색어를 함께 기록한다.
- 알 수 없는 허용값은 기본값으로 해석하고 필요하면 현재 방문 기록을 늘리지 않도록 `replace` 이동으로 정규화한다. 검색어 인코딩은 `URLSearchParams`로 처리한다.
- 무한 스크롤의 현재 페이지·로드한 페이지 수·스크롤 위치는 URL에 넣지 않는다.
- 예시: `/?q=리액트&target=title&sort=accuracy`, `/favorites?q=리액트&target=title&sort=accuracy`.

### 제출·화면 이동·방문 기록

- React Router의 `BrowserRouter`, `Routes`, `Route`, `Link` 또는 `NavLink`로 화면을 구성한다. 검색 제출과 화면 이동은 기본적으로 방문 기록을 추가하고, 정규화만 `replace` 이동을 사용한다.
- 화면을 바꿔도 `q`, `target`, `sort`를 유지한다. 찜 화면에서는 검색 결과를 표시하지 않고, 검색 화면으로 돌아오면 기존 조건을 사용한다.
- 상세검색 제출 시 전체검색 입력을 비우고 상세 조건을 적용한다. 전체검색 제출 시 상세검색 입력·조건을 초기화한다.
- 팝업 열기·입력·취소는 확정 조건을 바꾸지 않는다.
- 뒤로가기·앞으로가기는 React Router 위치와 URL에서 화면·확정 조건을 다시 읽는다. 검색 입력도 해당 조건에 맞춰 복원하고 팝업은 닫는다.
- 방문 기록 복원 자체는 새로운 방문 기록이나 최근 검색 기록을 추가하지 않는다.
- 새로고침은 경로와 조건을 복원한다. 결과 데이터는 필요하면 다시 요청하며, 스크롤 위치나 이전 페이지 수까지 복원을 보장하지 않는다.

### 구현 규칙

- `BrowserRouter`를 앱 루트에 두고 공통 셸 안에 검색·찜 경로를 중첩한다. 컴포넌트에서 History API를 직접 호출하지 않는다.
- 검색 파라미터의 파싱·정규화·직렬화는 순수 함수로 분리하고, URL 갱신은 React Router navigation API를 사용한다.
- React Query 키는 URL에서 읽은 확정 조건으로 만든다. Zustand에 같은 검색 조건이나 활성 화면을 저장해 URL과 왕복 복사하지 않는다.

## 대안과 선택 이유

| 대안                                      | 평가                                                                     |
| ----------------------------------------- | ------------------------------------------------------------------------ |
| 검색·화면 상태는 Zustand, URL은 부가 복사 | 양방향 동기화의 충돌·초기화 순서를 관리해야 한다.                        |
| URL 기준과 네이티브 History API 어댑터    | 추가 의존성은 없지만 화면 매칭과 위치 구독을 직접 관리해야 한다.         |
| URL 기준과 React Router (선택)            | 의존성과 라우트 구성이 추가되지만 화면 이동·방문 기록을 라우터에 맡긴다. |

## 결과와 트레이드오프

React Router 의존성과 경로 구성이 추가된다. 경로가 두 개뿐이므로 데이터 라우터나 파일 기반 라우팅 모드는 도입하지 않는다. 검색 조건은 URL을 기준으로 유지해 상태 중복을 피한다.

## 구현 시 확인

직접 `/`·`/favorites` 접속, 한글 검색어와 검색 조건 보존, 잘못된 파라미터 정규화, 입력 중 URL 불변, 화면 이동 후 조건 유지, 뒤로가기·앞으로가기, 새로고침 복원을 검증한다.
